# 운영 가이드 — 로컬 개발과 데이터 파이프라인

## 0. 사전 준비 (최초 1회)

| 항목 | 확인 | 없으면 |
|---|---|---|
| Node **22 LTS** | `node --version` | https://nodejs.org (22.x LTS) |
| **pnpm** (npm/yarn 금지) | `pnpm --version` | `corepack enable pnpm` |
| Docker Desktop | `docker --version` | https://docker.com — 또는 로컬 PostgreSQL 사용(아래 1-2) |
| Git | `git --version` | https://git-scm.com |

PowerShell 실행 정책 때문에 `.ps1` 이 막히면 그 창에서만 임시 허용:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

## 1. 클론부터 실행까지

### 1-1. 기본 경로 (Docker 사용)

```powershell
git clone https://github.com/likethisfeelo/petlifewith.me.git C:\petlifewithme
cd C:\petlifewithme
git checkout claude/build-from-spec-qkpshy

.\scripts\setup.ps1 -WithDevFixtures   # 아래 5단계를 한 번에
pnpm dev                                # http://localhost:3000
```

`setup.ps1` 이 하는 일:

1. 사전 준비 확인 (node 22+, pnpm, docker)
2. **`.env.local` 생성** — docker-compose 와 맞는 `DATABASE_URL` + 무작위 생성한
   `ADMIN_TOKEN`·`AUTH_SECRET`. (`.env.example` 은 변수명만 있는 목록이라 복사하지 않는다.
   복사하면 `DATABASE_URL` 이 비어 마이그레이션이 실패한다.)
3. `pnpm install`
4. `docker compose up -d db` + **접속 가능해질 때까지 대기**(`pg_isready` 폴링)
5. `pnpm db:migrate` → `pnpm seed` (+ `-WithDevFixtures` 면 `pnpm seed:dev`)

끝나면 관리자 토큰을 화면에 찍어준다. `.env.local` 이 이미 있으면 건드리지 않는다.

`-WithDevFixtures` 는 페이지 템플릿을 눈으로 확인하기 위한 **샘플 데이터**(샘플 스팟 8·메이커 2·
상품 4·요청함 1)를 넣는다. 전부 이름에 "샘플"이 붙고 `source='sample'` 이라 색인·사이트맵에서 제외되며,
실데이터를 넣기 시작하면 지우면 된다.

### 1-2. Docker 없이 (로컬 PostgreSQL 사용)

PostgreSQL 16 을 직접 설치했다면 DB·롤을 먼저 만들고 URL 을 넘긴다.

```powershell
# psql 에서
# CREATE ROLE app WITH LOGIN PASSWORD 'app_dev_password' CREATEDB;
# CREATE DATABASE app_dev OWNER app;

.\scripts\setup.ps1 -SkipDocker -DatabaseUrl 'postgresql://app:app_dev_password@localhost:5432/app_dev'
```

### 1-3. 수동으로 한 단계씩

```powershell
docker compose up -d db      # 또는 .\scripts\dev-db.ps1
pnpm install
pnpm db:migrate              # data/drizzle/ 의 SQL 적용
pnpm seed                    # 토픽 5 · 스팟유형 10 · 시군구 229 + 콘텐츠 18편
pnpm seed:dev                # (선택) 샘플 픽스처 — 프로덕션에서 실행 거부됨
pnpm dev
```

이 경로로 갈 때는 `.env.local` 을 직접 만들어야 한다. 루트에 하나만 두며(웹·데이터 공용),
최소 `DATABASE_URL`·`ADMIN_TOKEN`·`AUTH_SECRET` 이 있어야 앱과 관리자가 동작한다.
전체 변수 목록은 `.env.example`.

## 3. 콘텐츠 워크플로

1. `data/content/guides/*.md` 에 frontmatter(slug/title/topic/role/status/medicalAdjacent…)와 본문 작성
2. `pnpm --filter @app/data seed:content` 로 DB 반영 (slug 기준 upsert)
3. 관리자(`/admin/guides`)에서 상태 전환·태깅. **원본은 git** — 시드 재실행이 관리자 본문 수정을 덮어쓴다는 점에 유의
4. 발행 규칙: 의료 인접(medicalAdjacent) 편은 `vetReviewed` 전에 published 불가 — 시드·관리자·DB 3중 차단

임베드는 본문에 숏코드로만: `{{youtube:VIDEO_ID|창작자명|원본URL}}`, `{{instagram:게시물URL|창작자명|원본URL}}`.
창작자명·원본 URL 누락 시 렌더되지 않는다 (규칙 3-4 의 코드 강제).

## 4. 공공데이터 ETL

### 4-1. 인허가 CSV (스팟·사료제조업 시딩)

행정안전부 지방행정 인허가데이터(공공데이터포털 data.go.kr)의 CSV 를 내려받아
`data/raw/` (gitignore — 원본 덤프 커밋 금지) 에 두고 실행한다. 지원 데이터셋:

| `--dataset` | 원천 (행안부 인허가) | 스팟 유형 | 공개 정책 |
|---|---|---|---|
| `animal-beauty` | 동물미용업 | 미용·스파 | 공개 디렉토리 |
| `animal-boarding` | 동물위탁관리업 | 유치원·위탁 | 공개 디렉토리 |
| `animal-memorial` | 동물장묘업 | 장묘 | 공개 — **광고·순위 없음** |
| `animal-transport` | 동물운송업 | 이동·운송 | 공개 (행 단위가 차량이라 이름이 차량번호인 행이 많다 — noindex 게이트가 거른다) |
| `animal-pharmacy` | 동물약국 | 동물약국 | 공개 — **광고·순위 없음, 수의사 안내문 자동** (규칙 6-2) |
| `animal-drug-wholesale` | 동물용의약품 도매상 | 동물용의약품 도매 | **B2B 참고 디렉토리** — 광고 없음, 소비자 목록·집계와 분리 게시 |
| `animal-medical-device` | 동물용 의료용구 판매업 | 동물용 의료용구 판매 | **B2B 참고 디렉토리** — 상동 |
| `feed-manufacture` | 사료제조업 | (feed_licenses 원장) | 메이커 배지 근거 |

`spot_types.listed` 는 **소비자 디렉토리 배치 여부**다. listed=false(B2B 참고) 유형도
유형 허브·지역x유형·개별 페이지로 게시되지만(B2B 안내문 자동), 지역 허브의 혼합 목록·유형
분포·시도/시군구 집계에는 섞이지 않고 별도 "유통·산업 (B2B 참고)" 줄로만 연결된다.
색인·사이트맵 게이트(3곳·3항목)는 전 유형 동일하게 적용된다.
모든 공개 표기는 "행정안전부 지방행정 인허가데이터 확인 자료 · 기준일 · 관리번호"를 명시한다.

2026-08-25 실적재: 미용업 16,107 / 운송업 4,643 / 동물약국 20,796 / 도매상 1,316 / 의료용구 3,345
(스킵 1건 — 정부 원본이 2014년 폐지된 "청원군" 주소를 담은 폐업 행, 리포트에 기록됨).

**2026 행정구역 개편 대응** (`data/src/regions/regions.ts`):

- `전남광주통합특별시` 표기는 시군구명으로 옛 광주(구 5)·전남(시·군 22)에 결정적으로 귀속된다
  (`MERGED_SIDO_SLUGS`). URL 체계(/spot/시도/시군구)는 그대로다.
- 인천 신설 4개 구(제물포·영종·검단·서해)를 지역 테이블에 추가했다 (229 → 233).
  동구·서구는 기존 URL·데이터 보존을 위해 남아 있다.

```powershell
# 로컬 DB(.env.local) 대상
.\scripts\etl.ps1 -Dataset animal-beauty -File data\raw\beauty.csv -Encoding cp949 -ReferenceDate 2026-08-01
# 배포된 dev/prod DB 대상 — .env.deploy.<stage> 의 DATABASE_URL 을 자동 사용
.\scripts\etl.ps1 -Stage dev -Dataset animal-beauty -File data\raw\beauty.csv -Encoding cp949 -ReferenceDate 2026-08-01
# 스키마가 바뀐 뒤라면 적재 전에 마이그레이션·기준 시드 먼저:
.\scripts\db.ps1 -Stage dev
```

`.\scripts\db.ps1 -Stage dev -Task status` 로 접속 대상과 적재 현황(테이블·유형별 스팟 수)을
언제든 확인할 수 있다. 한글 파일명은 인자로 전달해도 된다 (.ps1 파일 내용만 ASCII 제한).

동작 방식 (추측 금지 원칙):

- CSV 헤더를 `data/src/etl/license/mappings.ts` 의 후보명과 대조해 해석한다. **필수 컬럼(사업장명·관리번호)을
  못 찾으면 발견된 헤더 목록을 출력하고 실패한다.** 실제 파일 헤더가 다르면 mappings.ts 에 후보를 추가한다.
- 관리번호 기준 upsert — 재실행해도 중복이 생기지 않는다.
- 주소는 `sanitizeRoadAddress` 가 **건물번호까지만** 남긴다 — 쉼표·괄호 뒤뿐 아니라 이어 쓴 동·호수·층·건물명도
  제거한다 (2026-09 강화. 이미 적재된 행은 ETL 재실행 때 정리된다).
- 에디토리얼 필드(설명·요금·예약 링크·유형 재분류)는 절대 덮어쓰지 않는다.
- 시군구 미귀속·미매핑 영업상태는 `data/reports/*.json` 리포트에 남는다. 리포트를 보고 지역 별칭이나
  상태 매핑을 보강한 뒤 재실행하는 것이 정상 루프다.
- 인코딩은 `--encoding auto`(기본)가 BOM/깨짐 휴리스틱으로 처리. 이상하면 `cp949` 또는 `utf8` 명시.
- `--dry-run` 으로 DB 반영 없이 리포트만 뽑을 수 있다.

### 4-2. 동물등록 현황 (노령견 비율)

농림축산검역본부 동물등록 현황(시군구별 × 출생연도별)을 CSV 로 준비해:

```powershell
pnpm etl:stats -- --file data/raw/dog_registration.csv --reference-date 2026-06-30
```

`--reference-date` 는 필수다(통계는 기준일이 곧 의미). 적재 후 지역 페이지의
"등록견 중 노령견 비율" 블록이 자동으로 채워진다. API 활용신청이 승인되면 fetch 단계만 추가하면 된다
(정규화·적재 재사용).

### 4-3. 직접 발굴 데이터 — 큐레이션 CSV (`data/content/**`)

셀프목욕·방문목욕·재활·기기 보유처는 공공데이터에 없다. 두 경로로 넣는다.

1. **관리자에서 한 건씩** — `/admin/spots/new` (출처 `direct`), `/admin/devices/new`, `/admin/rehab/new`.
2. **CSV 로 여러 건** — 사람이 정리한 목록을 `data/content/` 아래에 **커밋**하고 로더로 적재한다.
   원본 내보내기(숨고 등)는 커밋하지 않고 정리본만 남긴다.

큐레이션 CSV 규약 (`data/src/etl/lib/curated.ts`):

- 셀 값 **`#` = 미확인(비움)**. 필요한 컬럼인데 값이 없으면 `#` 을 넣는다. 신규 행에서는 비우고,
  **재적재에서는 기존 DB 값을 덮어쓰지 않는다** — 관리자에서 채운 값이 살아남는다.
- 필수 셀(이름·유형·지역 등)이 `#` 이면 그 행은 적재하지 않고 리포트에 남긴다. 값을 채운 뒤 재실행하면
  그때 들어간다.
- 외부키(`외부키` 컬럼 → `spots.external_ref` / `rehab_sites.external_ref`)로 upsert — 몇 번을 돌려도 중복이
  생기지 않는다. 키는 한 번 정하면 바꾸지 않는다 (예: `soomgo:10313516`, `rehab:0007`).
- 파일은 UTF-8(BOM) — 엑셀에서 열고 저장해도 된다. `비고` 컬럼은 정리자 메모로, 적재되지 않는다.

| 데이터셋 | 파일 | 로더 | 적재 대상 |
|---|---|---|---|
| `direct-spots` | `data/content/spots/*.csv` (예: `soomgo-grooming-2026-09.csv`) | `pnpm etl:direct -- --file <파일>` | `spots`(source=direct) + `spot_links` (+ 돌봄 유형은 `spot_service_areas`) |
| `care-sample` | `data/content/spots/care-sample-2026-09.csv` — 돌봄 파트너 **가상 예시 2건** | `pnpm etl:direct -- --file <파일>` (etl.ps1 은 `-Dataset care-sample`) | 위와 같음, source=sample |
| `rehab-sites` | `data/content/rehab/rehab-sites.csv` | `pnpm etl:rehab` | `rehab_sites` |

**direct-spots 컬럼**: `외부키 · 이름 · 유형(spot_types.slug: grooming / visiting-groom / visiting-bath /
self-wash / boarding …) · 지역("시도 시군구") · 주소 · 전화 · 영업상태(operating/…) · 기준일 · 소개 · 영업시간 ·
요금 · 주차 · 홈페이지 · 카카오톡 · 예약 · 네이버 · 인스타그램 · 블로그 · 기타링크("라벨|URL") ·
서비스지역(돌봄 유형만, "시도 시군구"를 `|` 로 구분) · 출처(비우면 direct, `sample` 이면 가상 예시) · 비고`.
링크는 종류 단위로 교체된다(파일에 없는 종류는 관리자 입력이 남는다). 서비스지역은 **추가만** 한다 — 관리자가
끈 노출(OFF)이나 관리자가 넣은 지역은 재적재가 건드리지 않는다. 주소는 적재 시 한 번 더
`sanitizeRoadAddress` 를 거쳐 **동·호수·층·건물명이 제거**된다 — 출장형(방문목욕·방문미용)은 주소를
`#` 으로 두고 지역만 싣는다 (1인 사업장 = 주거지, claude.md 5-6).

**rehab-sites 컬럼**: `외부키 · 병원명 · 지역 · 소재지(동 단위) · 전화 · 영업상태 · 치료법(슬러그를 | 로 구분,
`data/src/rehab/modalities.ts`) · 근거출처(공개) · 근거(공개, 사실만) · 확인수준(A/B/C, **관리 전용**) ·
내부메모(관리 전용) · 기준일 · 게시(Y/N)`. 치료법이 하나도 없는 행은 적재하지 않는다 — 치료법 없는 병원
목록은 "일반 동물병원 디렉토리"가 되기 때문이다 (claude.md 6-2). 담당 수의사 개인명 컬럼은 받지 않는다.

```powershell
# 로컬
.\scripts\etl.ps1 -Dataset direct-spots -File data\content\spots\soomgo-grooming-2026-09.csv -DryRun
.\scripts\etl.ps1 -Dataset direct-spots -File data\content\spots\soomgo-grooming-2026-09.csv
.\scripts\etl.ps1 -Dataset rehab-sites
# 배포 DB (스키마가 바뀐 뒤라면 먼저 .\scripts\db.ps1 -Stage dev)
.\scripts\etl.ps1 -Stage dev -Dataset direct-spots -File data\content\spots\soomgo-grooming-2026-09.csv
.\scripts\etl.ps1 -Stage dev -Dataset rehab-sites
```

### 4-3-1. 재활·한방·특수치료 페이지 (`/rehab`, `/rehab/[치료법]`)

**주어는 병원이 아니라 치료법**이다 (claude.md 6-2). 일반 동물병원 디렉토리·순위·추천·평점·광고를
만들지 않는다. 규칙이 코드로 고정된 지점:

- 공개 쿼리(`web/src/lib/queries/rehab.ts`)는 `internal_level`·`internal_note` 를 **select 하지 않는다**.
  확인 수준(A/B/C)이 등급처럼 읽히는 것을 원천 차단.
- 정렬은 시도 → 시군구 → 이름 가나다순. 게시(published) + 폐업 아님만 노출.
- 관리자 저장 시 공개 근거에 평가 표현(추천·최고·1위·잘하는…)이 있으면 거부, 게시하려면 근거 출처 필수,
  치료법 0개 저장 불가.
- 페이지마다 `RehabListNote`(병원 추천이 아님) + `MedicalNotice`(진료 대체 아님) + 출처·기준일 표기.
- 사이트맵: 시행처 3곳 이상인 허브·치료법 페이지만 (지역 페이지 게이트와 동일).

관리: `/admin/rehab` (검색·치료법·게시 필터, 편집·삭제). 스팟 디렉토리와는 별개 테이블이라
스팟 유형 `rehab`(재활·수중런닝 — 비병원 시설)과 섞이지 않고, 유형 허브에서 이 페이지로 안내만 한다.

  항상 들어간다: 전 페이지 `<head>` 의 `<meta name="google-adsense-account">` 와 `web/public/ads.txt`

  AdSense 의 "코드 스니펫" 검출에는 잡히지 않는다 — 확인은 메타 태그 또는 ads.txt 방식으로 한다.
  **운영 도메인에 배포된 뒤에만** 확인이 통과한다 (`https://petlifewith.me/ads.txt` 가 열리는지 먼저 본다).
  로드 범위는 통계보다 좁다 (`isAdsExcluded` + 테스트):
  - `production` 에서만. 승인되지 않은 dev 도메인에서는 요청을 보내지 않는다.
  - 경로·호스트 제외: 관리자, 사장님 포털(`/portal/*`, `service.`/`product.` 호스트), 정보 관리 요청 폼(`/claim/*`),
    **`/rehab/*`(의료 인접 무료 노출 전용)**.
  - 페이지 제외: 장묘·동물약국·B2B 유형의 장소·지역x유형·유형 허브 페이지(`monetizable=false`)와
    **의료 인접 게시글**(`medical_adjacent`) — 페이지가 `buildMeta({ ads: false })` 로
    `<meta name="petlife-ads" content="off">` 를 넣고, 로더가 그 값을 보고 건너뛴다.
  - 자동 광고는 전체 로드 때 페이지를 스캔한다. 검색 유입은 전체 로드라 제외 규칙이 그대로 지켜지고,
    사이트 안에서 클라이언트 이동으로 제외 페이지에 들어가면 이미 로드된 스크립트가 남지만 새 광고를
    끼워 넣지는 않는다. 광고 단위를 수동 배치하게 되면 이 규칙을 그 컴포넌트에서도 지킨다.

### 5-0. 관리자 계정 (사람별 토큰)

`ADMIN_TOKEN` 하나에 계정 여러 개를 담습니다 — `hee:<토큰1>,partner:<토큰2>`.
사람마다 다른 토큰을 주면 **개별 회수**가 되고, 패널 우측 상단에 로그인한 계정 라벨이 보입니다.

```powershell
.\scripts\admin-token.ps1 -Stage prod -List          # 등록된 계정 (토큰은 출력 안 함)
.\scripts\admin-token.ps1 -Stage prod -Add hee       # 계정 추가 + 토큰 1회 출력
.\scripts\admin-token.ps1 -Stage prod -Remove hee    # 회수
.\scripts\admin-token.ps1 -Generate                  # 파일은 그대로, 토큰만 생성
```

- `-Stage local` 은 `.env.local`(개발 서버 재시작), `dev`/`prod` 는 `.env.deploy.<스테이지>` 를
  고칩니다. 배포에 반영하려면 **GitHub 시크릿(`ENV_DEPLOY_DEV`/`ENV_DEPLOY_PROD`) 갱신 후 재배포** —
  스크립트가 그 절차를 출력합니다.
- 세션에는 토큰 지문만 들어갑니다. 계정을 빼거나 토큰을 갈면 **그 사람의 기존 로그인도 즉시 끊깁니다.**
- 토큰은 발급 시 한 번만 보입니다. 비밀번호 관리자 등 비공개 경로로 전달하고 채팅·커밋에 붙여넣지 않습니다.
- 마지막 한 계정은 지워지지 않습니다(아무도 못 들어가는 상태 방지).
- `service.` / `product.`(사장님 포털)는 **로그인이 없는 공개 랜딩 페이지**라 계정 설정이 없습니다.

### 5-1. 외부 링크 (선택적)

스팟과 메이커의 링크는 고정 항목이 아니라 **필요한 것만 골라 넣는 목록**입니다
(`spot_links` / `maker_links`). 업체마다 쓰는 채널이 다르기 때문입니다.

- 스팟: 홈페이지 · 카카오톡 · 예약 · 네이버 플레이스 · 인스타그램 · 블로그 · 기타
- 메이커: 자사몰 · 스마트스토어 · 카카오톡 · 인스타그램 · 크라우드펀딩 · 블로그 · 기타
- `http://` `https://` 만 저장됩니다. 주소가 빈 행은 저장 시 조용히 버려집니다.
- **링크도 정보 항목으로 셉니다.** 주소·전화만 있어 2항목이던 장소도 카카오톡 링크 하나로
  3항목이 되어 색인 대상이 됩니다 (claude.md 5-3).

### 5-2. 쿠팡 파트너스 링크

상품 편집의 구매 링크에서 구매처를 **쿠팡**으로 고르면 제휴 링크로 저장됩니다(직접 체크도 가능).
제휴 링크가 하나라도 렌더되는 페이지에는 수수료 고지가 자동으로 붙고, 링크에 `rel="sponsored"`
가 붙습니다. 본문 마크다운에 넣은 `link.coupang.com` 주소도 렌더러가 같은 처리를 합니다.

### 5-3. 미디어 업로드 (이미지·영상)

업로드는 처음부터 S3 전제다 (claude.md 10-1) — 서버는 presigned URL 만 발급하고
브라우저가 스토리지에 직접 올린다. 로컬에서는 MinIO 가 S3 를 대신한다.

```powershell
docker compose up -d minio        # minio-init 이 app-media 버킷을 만들고 공개 읽기로 연다
```

`.env.local` (setup.ps1 이 생성한 파일에는 이미 이 기본값이 들어 있다):

```
STORAGE_ENDPOINT=http://localhost:9000
STORAGE_BUCKET=app-media
STORAGE_ACCESS_KEY_ID=minio_dev
STORAGE_SECRET_ACCESS_KEY=minio_dev_password
NEXT_PUBLIC_ASSET_BASE_URL=http://localhost:9000/app-media
```

`NEXT_PUBLIC_*` 은 빌드에 인라인되므로 값을 바꾸면 dev 서버를 재시작한다.

- **미디어 라이브러리** `/admin/media` — 업로드(이미지 15MB·영상 300MB), 숏코드 복사, 삭제
- **본문 삽입** — 숏코드만 쓴다. DB 에는 오브젝트 키만 저장되고 URL 은 렌더 시 조립된다:
  `{{image:키|대체텍스트|캡션(선택)}}` · `{{video:키|캡션(선택)}}`
- **대표 이미지** — 게시글·스팟·메이커·상품 에디터의 업로드 필드. 페이지 상단과 공유 미리보기에 쓰인다
- **원칙**: 직접 촬영·제작한 것만. 인스타그램·유튜브에서 내려받은 이미지·스크린샷 업로드는 금지 (규칙 3-1).
  삭제하면 그 키를 쓰는 본문·OG 이미지가 깨진다 — 교체는 삭제가 아니라 새로 올려서 바꾼다.

배포 전환 시: 버킷을 S3 로, `NEXT_PUBLIC_ASSET_BASE_URL` 을 CloudFront 도메인으로 바꾸면 끝
(키는 그대로라 콘텐츠 수정이 필요 없다).

### 5-4. 페이지별 SEO / OG 설정

모든 공개 페이지는 og:title / og:description / og:url / og:image / og:type / twitter 카드가
자동으로 붙는다 (`web/src/lib/seo.ts` buildMeta). 기본값은 제목·요약·대표 이미지에서 만들어지고,
따로 다듬고 싶은 페이지만 에디터의 **"검색·공유 설정 (SEO / OG)"** 섹션에서 오버라이드한다.

- 대상: 게시글 · 스팟 · 메이커 · 상품 · 큐레이션 (검색·공유 제목 / 설명 / OG 이미지)
- 우선순위: 오버라이드 → 대표 이미지 → 사이트 기본 이미지(`NEXT_PUBLIC_DEFAULT_OG_IMAGE_URL`)
- 권장 길이(제목 60자·설명 155자)를 넘으면 카운터가 경고색으로 바뀌고, 70/200자를 넘으면 저장이 거부된다
- 게시글·큐레이션은 `og:type=article` + 발행·수정 시각, JSON-LD Article 에도 이미지가 들어간다

### 5-5. 게시글 작성 (블로그형)

`/admin/guides/new` 에서 바로 씁니다. 마크다운 파일(`data/content/guides/*.md`)로 관리하는
경로와 공존합니다 — **같은 슬러그를 쓰면 `seed:content` 재실행 시 본문이 덮어써지니**, 관리자에서
쓴 글은 마크다운에 없는 슬러그를 쓰세요. 저장하면 편집 화면으로 이동해 태깅을 붙일 수 있습니다.

저장 시 막히는 것들: 의료 인접 편의 즉시 발행, 감수자명 없는 감수 완료 표시, 기준일 없는 등록
확인 배지, 창작자명·원본 링크·요약이 빠진 큐레이션 항목, `http(s)` 가 아닌 링크.

### 5-6. 게시판 3분할 — 큐레이션 콘텐츠 · 일반 게시판 · 부위별 게시판

한 토픽의 발행 글은 별도 테이블 없이 세 묶음으로 갈린다 (`web/src/lib/guide-order.ts`, 테스트 있음).

| 게시판 | 무엇이 들어가나 | 정렬 | 경로 |
|---|---|---|---|
| **큐레이션 콘텐츠** | `guides.curated = true` — 운영진이 발행한 글(기본 켜짐) + 운영진이 골라 올린 회원 글 | `curated_order`(1~9) 순 → 최신순 | 토픽 페이지 맨 위 9편, 전체는 `/topic/[토픽]/curated` |
| **일반 게시판** — 노견생활은 "일반 - 노령견 생활 공유 게시판" | 회원이 쓴 글 전체(`author_user_id` 있음). 큐레이션에 올라가도 여기 남는다 | 최신순 | `/topic/[토픽]/challenge` (처음 이름 "도전 게시판"의 주소 그대로) |
| **부위별 게시판** | `category` 가 있는 글. 누구나 질문·글을 올리고 댓글을 단다 | 대표(`area_order` 1~3) → 최신순 | `/topic/[토픽]/[카테고리]` + 신체 지도 패널 |

- **토픽 페이지 배치**: 머리말(영문 키커 `Long Live Petlifewithme · Curated Content` + 토픽명) 바로 아래
  **큐레이션 카드 그리드**(섬네일 카드, 최대 `LATEST_ON_TOPIC`=9편, "큐레이션 전체 보기 →") → 신체 지도(자기 제목
  "신체 영역별로 살펴보기") → 부위별 게시판 칩 → 클러스터 지도 → 돌봄 배너. 토픽 페이지에는 일반 게시판 입구를 두지 않는다.
- **게시판 이름**: 토픽별 `web/src/lib/boards.ts` — 종류 표시 "일반"(제목에서는 작은 칩) + 이름(노견생활 "노령견 생활 공유
  게시판", 정해 두지 않은 토픽은 "<토픽명> 생활 공유 게시판"). 제목·빵부스러기는 "일반 - 노령견 생활 공유 게시판".
- **큐레이션 페이지 하단 = 일반 게시판 전체**(`components/challenge-board.tsx`, `/challenge` 와 같은 목록). 큐레이션은
  이 게시판에서 운영진이 대표를 골라 위에 세워 둔 것이라는 관점 — 큐레이션에 올라간 회원 글에는 "큐레이션 선정" 칩.
  대표 이미지가 없으면 발자국 자리표시(관리자 게시글 편집의 대표 이미지 업로드로 채운다).
- **큐레이션 지정(관리자)**: 게시글 편집 화면 "큐레이션 콘텐츠" — `큐레이션에 노출` 체크 + `노출 순서` 1~9.
  운영진이 새로 쓴 글은 기본 켜짐, 회원 글은 승인한 뒤 여기서 켜야 올라간다. 순서를 주면 체크는 자동으로 켜진다.
  토픽당 순번 하나에 글 하나(DB 부분 유니크 `guides_topic_curated_uq`), 발행 글만. 마크다운 시드는 frontmatter
  `curated: false` 로 뺄 수 있다(부위별 Q&A 시드는 항상 false).
- **부위 대표(관리자)**: 편집 화면 "부위 대표 순번" 1~3 — 카테고리를 지정한 발행 글만. 신체 지도 패널(최대 3편)과
  부위별 게시판 맨 위에 "대표 N" 배지로 뜬다. 부위당 순번 하나에 글 하나(`guides_area_order_uq`).
- **카테고리(위치)**: 토픽별 정의 `data/src/guides/categories.ts`. 노견생활은 신체 영역 8개
  (관절·보행 / 심장·호흡 / 인지·수면 / 눈·귀 / 치아 / 체중·식욕 / 털·체취 / 엉덩이·배변).
  **지정하지 않으면 부위별 게시판에는 안 보인다** — 관리자가 편집 화면에서 지정하거나 회원이 글쓰기에서 고른다.
  마크다운 시드는 frontmatter `category:` 로 지정하며 정의에 없는 값이면 시드가 실패한다.
- **신체 지도**: 노견생활 토픽의 강아지 그림(`web/src/components/senior-body-map.tsx`). 부위에 올리면 이름, 누르면
  오른쪽 패널에 그 부위의 글(대표 → 최신, 최대 3편, 제목 = 질문)과 **"○○ 영역별 정보 더 보기" 버튼**이 뜬다.
  `/topic/senior-life#joint` 처럼 해시로 부위를 지정해 들어올 수 있다.
- **회원 글의 흐름**: `/write` → 승인 대기(pending) → 관리자 승인(published) → **일반 게시판**에 나타남 (+ 카테고리를
  골랐으면 부위별 게시판) → 운영진이 원하면 편집 화면에서 큐레이션 노출을 켜 **큐레이션 콘텐츠**에도 올린다.
  회원이 발행된 글을 고치면 다시 승인 대기로 돌아가고 큐레이션 순서·부위 대표는 풀린다(큐레이션 노출 체크는 남는다).
  설정(`/admin/settings`)에서 승인 대기를 끄면 저장 즉시 공개되고 수정해도 공개가 유지된다 (5-10).
- 큐레이션·일반 게시판은 발행 글 3편 이상이면 색인하고 사이트맵 core 섹션에 넣는다(`sitemapTopicBoards`).
  큐레이션 페이지에는 카테고리 칩을 두지 않는다 — 부위 분류는 부위별 게시판의 것이다.

### 5-7. 회원 · 회원 글 · 댓글

읽기는 로그인 없이. **글과 댓글은 회원만** 쓴다 (2026-09 도입).

- **인증**: 이메일 + 비밀번호(자체, `web/src/lib/password.ts` scrypt) + 서명 쿠키(`member_session`).
  쿠키에는 사용자 id 와 `session_version` 만 있어 차단·비밀번호 변경 시 즉시 끊긴다.
  이메일 확인 메일은 아직 보내지 않는다(발송 인프라 없음). Cognito 로 옮길 때는 `lib/auth.ts` 의
  회원 세션 발급부와 로그인 액션만 바꾸면 된다 — `users.cognito_sub` 는 그대로 비어 있다.
- **화면**: `/signup` `/login` `/me`(내 글·닉네임·비밀번호) `/write`(새 글) `/write/[id]`(내 글 수정).
  헤더 오른쪽 메뉴는 마운트 후 `/api/me` 로 로그인 상태를 알아낸다 — 페이지 HTML 은 로그인과 무관하게
  같아서 ISR 이 유지된다.
- **회원 글 흐름**: 저장하면 `pending`(승인 대기) → 관리자가 게시글 화면에서 **승인·발행** →
  공개(최신 글 맨 위). 회원이 발행된 글을 고치면 다시 승인 대기로 돌아가고 고정도 풀린다.
  승인 대기 글은 회원당 5편까지. 회원 글의 외부 링크는 `rel="nofollow ugc"`, 페이지에 "회원 글 ·
  닉네임" 배지와 감수 아님 안내가 붙는다. 의료 인접 플래그는 관리자만 켤 수 있고, 켜면 감수 게이트가
  그대로 적용된다.
- **댓글**: 로그인 회원이 바로 등록(시간당 20건). 평문으로 저장·표시하고 링크를 활성화하지 않는다.
  본인 삭제 가능. 관리자는 `/admin/comments` 에서 숨김·삭제.
- **관리**: `/admin/members` — 이메일은 여기서만 보인다, **차단/해제**(차단 즉시 로그인 끊김).
  `/admin/guides?status=pending` — 승인 대기 필터 + 목록에서 바로 승인.
- **개인정보**: 공개되는 것은 닉네임뿐. 이메일은 로그인·안내 용도라고 가입 화면에 명시한다.

### 5-8. 돌봄 파트너 (펫시터·펫산책) — 지역별 5자리 · 노출 ON/OFF · 예약 신청

펫시터(`pet-sitter`)·시간제 시터(`hourly-sitter`, 2026-09 신설)·펫산책(`dog-walk`) 유형은 **시설이 아니라
사람이 움직이는 서비스**라 주소 대신 **서비스 지역**(시군구, `spot_service_areas`, 0008)으로 노출된다. 통칭은
"돌봄 파트너", 사람 호칭은 펫시터 / 시간제 시터 / 도그워커 (`data/src/care/care.ts`).

- 두 시터는 **돌봄 장소**로 갈린다. 펫시터 = **보호자 집으로 와서** 돌보는 방문 돌봄. 시간제 시터 = **시터 집에
  아이를 맡기는** 시간 단위 돌봄. 둘은 별도 유형·별도 디렉토리다(`/spot/type/hourly-sitter`). 새 유형은 `seed:base`
  로 들어간다 — 배포 DB 는 `.\scripts\db.ps1 -Stage <stage>` 한 번.
- `/topic/senior-life` **하단 돌봄 배너**(`components/care/care-entry-banner.tsx`): 섹션 두 개(세로로 쌓임, 각 섹션 안에서 큰 카드 버튼이 가로 배치 — 위 3개·아래 2개) — "직접 강아지와 함께
  방문해요"(아이가 가는 곳 — 유치원·데이케어 → `boarding`, 시간제 시터 → `hourly-sitter`) / "집으로 오거나 집
  근처에서"(사람이 오는 서비스 — 펫시터 →
  `pet-sitter`, 산책 → `dog-walk`). 유치원·데이케어는 같은 인허가 유형(동물위탁관리업)이라 목적지가 같고 문구만
  다르다. 항목·줄 배치는 컴포넌트의 `GROUPS` 배열 한 곳에서 바꾼다. 등록 수 0 이면 "등록 받는 중".

- 공개: 시설 디렉토리와 같은 셸(5-9). 유형 허브 `/spot/type/pet-sitter|hourly-sitter|dog-walk` 는 좌측 시도(17)→시군구
  타일 지도(배지는 노출 중 파트너 수, 시도 배지는 사람 수) + 우측 파트너가 있는 시도·시군구 현황. 시군구 타일과 현황 칩은
  **지역x유형 페이지** `/spot/<시도>/<시군구>/pet-sitter` 로 가는 진짜 링크이고, 그 페이지가 같은 지도(이 지역 강조) + 우측
  **5자리**(빈 자리는 "비어있습니다")를 서버 렌더한다 — 유치원 지역 페이지와 같은 구조의 SEO 페이지. 허브는 첫 파트너의
  1순위 지역이 있는 시도를 펼친 채 시작하고, 최근 본 지역이 있으면 그 지역 페이지로 가는 제안 배너를 띄운다.
  파트너 3명 미만이면 noindex, 예시(sample)는 세지 않는다(사이트맵도 같은 기준, 서비스 지역 기준). 개별 페이지(`/place/…`)에는
  활동 지역(지역x유형 페이지 링크)과 예약·상담 줄. 시도 페이지 유형 칩·지역 허브 유형 분포에서 돌봄 유형의 수는 주소가
  아니라 서비스 지역 기준(`listCareCountsByRegion`)이며, 주소 기준 유형 집계는 돌봄 유형을 뺀다.
- 지역 단위: 서울·광역시는 구, 경기·도는 시·군 — `regions` 테이블 그대로(일반구는 시로 합침: 분당구 → 성남시).
- 카드 버튼: **예약 신청**(카드 안에서 펼쳐지는 폼) · **카카오톡 상담**(`spot_links.kind=kakao` 가 있을 때,
  없으면 "준비 중") · 자세히. 순위·평점 없음, 상세 주소 없음(활동 지역만) — claude.md 5-6.
- 관리자 `/admin/care`: 유형·시도별로 **지역 → 등록된 파트너 → 노출 ON/OFF**. 지역 x 유형당 노출 자리는
  `MAX_EXPOSED_PER_AREA`(5) — 켤 때 자리가 차 있으면 안내로 돌아온다. 스팟 편집기(`/admin/spots/[id]`)에서
  유형을 펫시터·펫산책으로 고르면 "서비스 지역 · 노출" 편집기가 나타나 지역 추가·순서·ON/OFF 를 정한다
  (저장 시 같은 상한 검사). 노출은 켜져 있어도 영업 상태가 `operating` 이 아니면 공개 목록에 나오지 않는다.
- 예약 신청: `booking_requests` 에 저장 → **슬랙 Incoming Webhook** 으로 알림 → 운영자가 파트너에게 연결 →
  `/admin/bookings` 에서 "처리됨" 표시. 그 이상의 상태 흐름은 두지 않는다(프로세스 최소). 신청자 이름·연락처는
  관리자 화면과 슬랙에만 가고, 원 IP 는 저장하지 않는다(해시로 시간당 5건 제한 + 봇 함정 칸).
  - 슬랙 설정: 슬랙 앱 → Incoming Webhooks → 채널 선택 → 생성된 `https://hooks.slack.com/...` URL 을
    `.env.local`(로컬) 또는 `.env.deploy.<stage>`(배포, GitHub Secrets `ENV_DEPLOY_*` 갱신 후 재배포)의
    `SLACK_BOOKING_WEBHOOK_URL` 에 넣는다. URL 은 시크릿 — 채팅·커밋에 붙여넣지 않는다. 비어 있으면 저장만 되고
    `/admin/bookings` 에 "슬랙 미전송"으로 남는다. 요청함(5-12)은 `SLACK_REQUESTS_WEBHOOK_URL` 이 따로 있으면 그쪽으로.
- 파트너 등록은 `/portal/care`(요청함 `care_partner`, 5-12)로 받는다 — 지역x유형 페이지의 빈 자리 링크가 유형·지역을 채워 보낸다.
- 가상 예시 2건(`data/content/spots/care-sample-2026-09.csv`, `출처=sample`): 마포 펫시터(마포·서대문·용산),
  분당 도그워커(성남·용인). 화면에 "예시" 배지가 붙고 색인·사이트맵에서 빠진다. 실제 파트너가 들어오면
  관리자에서 지우거나 CSV 행을 교체한다.

### 5-9. 스팟 디렉토리 레이아웃 — 좌측 지도, 우측 목록 (SEO 페이지 = 지도 페이지)

시설 디렉토리(유형 허브·시도·지역 허브·지역x유형)는 한 셸(`web/src/components/spot/spot-directory.tsx`)로 그린다.
좌측은 시도(17) → 시군구 타일 지도(`components/care/care-map.tsx` 링크 모드), 우측은 서버가 렌더한 목록이다.

- **주소는 그대로**: `/spot/type/[유형]`, `/spot/[시도]`, `/spot/[시도]/[시군구]`, `/spot/[시도]/[시군구]/[유형]`. 지역x유형
  페이지가 곧 SEO 페이지("서초구 유치원·위탁")이자 지도 페이지다 — 시군구 타일이 진짜 링크라 크롤러는 유형마다 전
  지역 링크를 보고, 사람은 타일을 누르면 주소만 바뀌며 지도는 그대로 남는다(같은 라우트 사이 소프트 내비게이션).
  브라우저에는 선택한 지역의 목록만 내려간다. 시도 타일은 펼치기(클라이언트 상태)만 하고 시도x유형 페이지는 두지 않는다.
- **유형 허브**: 지도(아무 지역도 선택 안 됨) + 우측 시도별 현황(시도 페이지로 가는 링크). 배지는 그 유형의 시군구별 수.
- **시도 페이지**: 지도가 그 시도로 펼쳐진 채 시작. 지도 위 **유형 칩**(전체 / 그 시도에 있는 유형)을 고르면 배지와
  타일 링크가 그 유형의 지역x유형 페이지로 바뀐다. 우측은 시군구별 현황(지역 허브 링크)과 유형별 링크.
- **지역 허브·지역x유형**: 지도에 그 시군구가 강조되고 시도가 펼쳐진다. 지역 허브 배지는 전체 스팟 수, 지역x유형은 그 유형 수.
- **모바일**: 지도는 목록 위 "지역 고르기" 접이식으로 들어가고 목록이 먼저 보인다.
- 색인 게이트(3곳 미만 noindex)·사이트맵·ItemList 구조화 데이터는 그대로다.
- **돌봄 파트너**(펫시터·시간제 시터·도그워커)도 같은 셸이다(5-8). 배지는 서비스 지역 기준 노출 중 파트너 수, 단위는 "명"
  (셸의 `countsBySido`·`total`·`unit` 로 넘긴다 — 한 사람이 여러 구를 맡아도 시도 배지는 1). 지역x유형 페이지 우측이 5자리
  (`components/care/care-slots.tsx`, 예약 신청·카카오톡 상담). 옛 해시 선택 허브(`care-directory.tsx`)는 없앴다.

### 5-10. 놀이 영상 피드 · 회원 사진·영상 업로드 · 설정 (0010)

놀이 클러스터(`/topic/play`)는 글 목록이 **영상 카드**다. 위에 **큐레이션 콘텐츠 3편**(`PLAY_CURATED`), 그 아래 **일반 - 놀이 생활 공유
게시판 6편**(회원 글, `PLAY_BOARD`)이 각각 "전체 보기"와 함께 뜨고, 카드는 섬네일 + 마우스 호버 미리보기 + 클릭 → 글.
맨 아래에는 노견생활 돌봄 배너와 같은 디자인의 **놀이 입구 배너**(`components/care/care-entry-banner.tsx` `PlayEntryBanner`):
"함께 가서 놀아요"(수영장 `pool` · 운동장 `playground` · 카페 `cafe`) / "사람과 함께"(펫시터 · 펫산책 · 펫모임 `/meetup`, 준비 중).
`cafe`(반려동물 동반 카페)는 2026-09 신설 유형 — 인허가 데이터에 없어 직접 발굴·업체 등록으로 채운다(`seed:base`).
큐레이션·일반 게시판 전체 페이지는 그대로다. 노견생활 등 다른 토픽의 구조는 바뀌지 않았다.

- **대표 영상** `guides.hero_media` — `video:<키>` / `youtube:<ID>` / `instagram:<URL>`. 비우면 본문 첫 영상. 편집 화면(관리자·회원)의
  "대표 영상" 선택은 본문에 든 영상만 고를 수 있다. 규칙·파싱은 `web/src/lib/media-ref.ts`(테스트 있음).
- **섬네일 우선순위** 대표 이미지 → 업로드 영상 포스터(`media_assets.poster_key`) → 유튜브 공식 섬네일(i.ytimg.com, 재호스팅 아님) →
  본문 첫 사진 → 발자국 자리표시. 영상이 없는 글은 사진 카드(호버 없음).
- **호버 미리보기** `components/media/media-card.tsx`: 업로드 영상은 `<video muted>` 재생, 유튜브는 음소거 자동재생 공식 임베드로 교체
  (iframe 은 클릭을 먹지 않는다), 인스타그램은 섬네일만. 터치 기기는 호버 없이 탭 → 글. 유튜브 호버는 플레이어를 불러오므로
  무거우면 `MediaCard` 의 youtube 분기만 빼면 된다.
- **놀이 글 우측 패널** `/guide/[slug]`: 놀이 글에 태그된 상품(구매 링크·수수료 고지)·브랜드(홈페이지·인스타·스마트스토어 `maker_links`)·
  장소·기기가 본문 오른쪽 고정 칸에 뜬다(모바일은 본문 아래). 태그는 관리자가 게시글 편집에서 붙인다 — 회원 글도 같다.
  다른 토픽은 본문 아래 패널 그대로.
- **업로드(관리자·회원 공용)** `app/upload-actions.ts` + `lib/media-upload.ts`: presign → 브라우저가 S3 에 직접 PUT → 등록.
  영상은 등록 전에 브라우저가 **포스터(첫 화면)** 를 잡아 이미지 자산으로 먼저 올리고 길이(`duration_sec`)와 함께 등록한다.
  회원 자산에는 `uploader_user_id` 가 남고, 회원 글 본문은 **자기 자산 키만** 참조할 수 있다(저장 시 검사). 시간당 업로드 수
  `MAX_UPLOADS_PER_HOUR`(40).
- **영상 자르기(기본 3분)** `components/media/use-media-uploader.tsx`: 영상을 고르면 자르기 대화상자가 뜬다. 길이 상한
  (설정 `maxVideoSeconds`, 기본 180)을 넘으면 잘라야 올릴 수 있고, 안이면 "이대로 올리기". 자르기는 mediabunny 로 브라우저 안에서
  **코덱 복사**(재인코딩 없음) — 키프레임 경계까지 넓히므로 몇 초 길어질 수 있어 서버는 상한 +10초까지 받는다. 브라우저가 못 여는
  코덱은 자를 수 없다는 안내가 뜬다.
- **편집기 툴바** `components/media/media-toolbar.tsx`(관리자 게시글 편집·새 글, 회원 글쓰기 공용): 📷 사진 · 🎬 영상 · ▶ 유튜브 링크 ·
  ◎ 인스타그램 링크. 링크는 주소 + 창작자 이름을 받아 숏코드로 커서 자리에 넣는다(창작자·원본 링크 없는 임베드는 렌더되지 않는다,
  운영 규칙 3-4). 인스타그램은 **게시물(/p/)·릴스(/reel/)만**, 스토리·프로필은 거부(`instagramPermalink`).
- **설정 `/admin/settings`** (`site_settings.member_media`, 기본값 `lib/settings.ts`): 글당 사진 수·영상 수(0 = 제한 없음), 사진·영상
  용량 상한(0 = 시스템 상한 15MB/300MB), 영상 최대 길이(초, 관리자에게도 적용), **승인 대기**(끄면 회원 글이 저장 즉시 공개되고
  수정해도 공개 유지). 처음 값: 개수·용량 제한 없음, 180초, 승인 대기 켬.
- 검증(로컬): 가짜 S3(`scratchpad/fake-s3.mjs`, :9000) + `STORAGE_*`/`NEXT_PUBLIC_ASSET_BASE_URL` 로 dev 서버를 띄우고, 브라우저에서
  mediabunny 로 만든 200초 webm 을 회원 글쓰기에서 올려 3분으로 자르기 → 포스터·길이 등록 → 승인 → 피드 카드 호버 재생 → 글 페이지,
  설정(영상 1개 제한·승인 대기 끔) 반영, 유튜브 호버 iframe, 인스타그램 스토리 거부를 확인했다.

### 5-11. 글쓰기 흐름 · 블록 편집기 · 태그 (0011)

- **글쓰기 흐름(회원 `/write`)**: ① 주제 고르기(노견생활·놀이·케어·힐링·간식 카드) → ② 카테고리 고르기(주제에 카테고리가 있을 때만 —
  지금은 노견생활의 신체 부위, "전체" 선택 가능) → ③ 편집. 편집 화면 위에 고른 주제·카테고리가 보이고 "바꾸기"로 돌아간다(쓰던 내용은
  남는다). 게시판의 글쓰기 버튼(`/write?topic=…&category=…`)으로 들어오면 그 단계는 건너뛴다. 수정은 바로 편집 화면.
- **블록 편집기** `web/src/components/editor/block-editor.tsx`(관리자 게시글 편집·새 글, 회원 글쓰기 공용): 본문을 블록(본문·제목·소제목·
  사진·영상·유튜브·인스타그램)으로 보여 준다. 사진·영상은 버튼이나 **끌어다 놓기**로 올리고 올라간 것은 숏코드가 아니라 **섬네일**로
  보인다. 블록마다 종류 바꾸기·위아래 이동·삭제, 블록 사이 "＋ 여기에 추가". 본문 블록 안에서는 마크다운(**굵게**, 링크, 목록)을 쓰고
  B·링크 버튼이 감싸 준다. "마크다운" 버튼으로 원문을 직접 고칠 수 있다. 저장 형식은 그대로 마크다운 — 왕복 규칙은
  `web/src/lib/blocks.ts`(테스트 있음): 빈 줄로 나뉜 덩어리 = 블록, `##`→제목, `###`→소제목(`#` 하나도 제목 — 글 제목이 H1),
  숏코드 한 줄 = 미디어 블록, 나머지는 본문 블록.
- **태그** `guides.tags text[]`(0011, GIN): 글과 별도로 붙는 키워드이면서 본문 안에 `#태그` 로도 쓴다. 편집기의 태그 칸(칩 입력,
  추천 = 많이 쓰인 태그)과 본문의 `#태그` 를 저장할 때 합친다(`lib/tags.ts` mergeTags — 칸 10개, 합쳐서 20개). 정규화: `#` 제거·공백 제거·
  소문자·30자·글자 하나 이상. 본문의 `#태그` 는 렌더 때 `/tag/<태그>` 링크(칩 모양 `.md-tag`)가 되고, 제목·코드·링크·주소의 `#` 은 건드리지
  않는다. 글 페이지 머리에 태그 칩, 태그 페이지 `/tag/[태그]` 는 모든 토픽의 글을 최신순으로 보여 주고 3편 미만이면 noindex(사이트맵 core 에
  3편 이상만). 마크다운 시드는 frontmatter `tags:`.

### 5-12. 요청함 — 업체 등록 · 정보 관리 · 지역 상단 노출 · 돌봄 파트너 등록 (0012)

사장님·파트너 쪽 절차는 전부 **요청 → 슬랙 알림 → 관리자가 처리** 한 흐름이다. 로그인·셀프 편집·결제 연동 없음.
요청은 `service_requests`(0012, 예전 `claims` 를 흡수 — 기존 클레임 행은 `spot_claim`/`maker_claim` 으로 옮겨짐)에 쌓이고,
관리자는 `/admin/requests` **요청함** 한 곳에서 본다. 종류(`kind`)는 다섯 가지:

| 종류 | 공개 폼 | 처리 바로가기 |
|---|---|---|
| `spot_register` 업체 등록 | `/portal/spot` (service. 서브도메인) — 업체명·업종(공개·수익화 유형, 돌봄 제외)·지역·주소·전화·링크·소개 | **스팟으로 등록 (값 채워짐)** → `/admin/spots/new?from=<요청>` 에 이름·유형·지역·주소·링크가 채워진다. 등록하면 요청에 스팟이 연결되고 상태가 "처리 중" |
| `spot_claim` / `maker_claim` 정보 관리 | 업체·메이커 페이지의 "정보 관리 요청 (무료)" → `/claim/spot|maker/<id>` | **편집기에서 반영** → 스팟·메이커 편집기 |
| `promo_slot` 지역 상단 노출(유료) | `/portal/promo?spot=<id>` (업체 페이지 "지역 상단 노출 신청 (유료)") 또는 `/portal/promo` (미등록 업체 — 업체명·지역) — **A·B·C 형** 라디오 | **입금 확인** 토글(`paid_at`) → **지역 상단 노출 켜기/끄기**(`promotions`, 기존 토글 재사용). 미등록 업체면 먼저 등록한 뒤 "업체 연결"(스팟 id) |
| `care_partner` 돌봄 파트너 등록 | `/portal/care?type=<유형>&region=<지역>` (지역x유형 페이지 빈자리 "이 지역 펫시터로 등록", 유형 허브 안내) — 호칭·활동명·활동 지역 최대 5곳·소개·요금·시간·카카오톡. **주소는 받지 않는다** | **파트너로 등록 (값 채워짐)** → 서비스 지역이 노출 ON 으로 채워진 등록 폼 (5자리 상한 검사는 저장 때) |

- 상태는 접수 → 처리 중 → 완료 / 거절 네 단계뿐. 카드의 버튼으로 바꾸고 운영 메모(`admin_note`)를 남긴다. 대시보드 "미처리 요청" = 접수 상태 수.
- **결제는 수동**: 유료 노출 요청이 오면 슬랙·요청함에서 보고 계좌나 결제 링크를 안내 → 입금 확인 토글 → 노출 켜기. PG 연동은 뒤로 미룬다.
  형별 설명·요금 문구는 `/admin/settings` "지역 상단 노출 형 안내"(`site_settings.promo_plans`)에 적으면 `/portal/promo` 카드에 보이고, 비우면 "요청 후 안내".
- 개인정보: 신청자 이름·연락처·사업자번호는 요청함(관리자)과 슬랙에만 간다. 원 IP 는 저장하지 않고 해시로 **시간당 5건** 제한 + 봇 함정 칸(`website`).
  등록 폼에서 스팟을 만들 때 연락처는 옮기지 않는다 — 스팟 `phone` 은 폼의 "업체 전화" 칸이다.
- 슬랙: `SLACK_REQUESTS_WEBHOOK_URL` 이 있으면 그 채널로, 없으면 `SLACK_BOOKING_WEBHOOK_URL`(예약 신청) 채널로 간다. 둘 다 없으면 저장만 되고
  카드에 "슬랙 미전송". 메시지에는 요청 번호·종류·요약·담당자·연락처와 요청함 링크가 들어간다.
- 검증 순수 함수는 `web/src/lib/requests.ts`(테스트 있음), 액션은 `web/src/app/request-actions.ts`(공개) · `web/src/app/admin/request-actions.ts`(관리자).
- 배포 DB: `.\scripts\db.ps1 -Stage <stage>` 로 0012 를 적용한다 (claims → service_requests 이전 포함).

### 5-13. 펫모임 — 내 지역 3곳 · 회원이 여는 모임 · 참여 회원만 보는 게시판 (0013)

`/topic/play` 하단 배너의 "펫모임" 카드가 `/meetup` 으로 온다. 회원이 **내 지역**(시·군·구, 최대 3곳, `user_regions`)을 골라 두면
그 지역의 모임에 참여하거나 직접 만든다. 승인 없음 — 만들면 바로 열리고(`meetups.status=open`) 관리자는 **숨김만** 한다.

- **비회원**에게는 지역별 집계 "모임 n개 · m명 참여 중"(`regionSummaryText`)만 보인다 — 지도 배지(열린 모임 수)와 지역 패널, 모임 페이지 모두.
  모임 이름·소개·참여자는 회원에게만, **게시판(`meetup_posts`)은 참여 회원에게만**. 그래서 `/meetup*` 은 전부 noindex·광고 제외.
- 허브 `/meetup`: 좌측 지역 지도(`components/meetup/meetup-map-shell.tsx`, 시군구 타일 = `/meetup?region=<id>`), 우측 패널.
  회원 첫 화면은 내 지역 칩 → 내 지역의 모임 → 참여 중인 모임. 지역을 고르면 그 지역 모임 목록(열림 먼저) + "이 지역에 모임 만들기"(내 지역일 때).
- 만들기 `/meetup/new`(내 지역이 없으면 지역 고르기부터): 이름·지역(내 지역 가운데)·다음 모임 일시·만나는 곳(공원·카페 이름 — 주소 아님)·정원·소개.
  하루 3개. 슬랙(`SLACK_REQUESTS_WEBHOOK_URL`, 없으면 예약 웹훅)으로 "새 펫모임" 알림 → `/admin/meetups`.

## 8. 자주 막히는 것

| 증상 | 원인과 해결 |
|---|---|
| `환경변수 DATABASE_URL 가 없습니다` | `.env.local` 이 없거나 값이 비어 있다. `.env.example` 을 그대로 복사하면 값이 전부 비어 있으니 `setup.ps1` 로 생성하거나 직접 채운다 |
| `ECONNREFUSED 127.0.0.1:5432` | DB 가 안 떠 있다. `.\scripts\dev-db.ps1` 또는 `docker compose up -d db`. 컨테이너 기동 직후 몇 초는 접속이 거부될 수 있다 |
| `.ps1` 실행이 차단됨 | `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` 후 재실행 |
| `pnpm: 명령을 찾을 수 없음` | `corepack enable pnpm`. npm·yarn 은 쓰지 않는다 |
| `pnpm build` 가 DB 오류로 실패 | 빌드가 페이지를 미리 생성하며 DB 를 읽는다. 빌드 전에 DB 를 띄워둔다 |
| 관리자 로그인이 계속 실패 | `.env.local` 의 `ADMIN_TOKEN` 과 입력값이 정확히 같아야 한다. `AUTH_SECRET` 이 비어 있어도 로그인은 실패한다 |
| 발행한 글이 안 보임 | `status: published` 인지, 의료 인접 편이면 `vetReviewed: true` 인지 확인 (감수 전 발행은 차단된다) |
