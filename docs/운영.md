# 운영 가이드 — 로컬 개발과 데이터 파이프라인

## 1. 처음 시작 (Windows, PowerShell)

```powershell
# 저장소 루트에서
.\scripts\setup.ps1                  # env 생성 + pnpm install + DB 컨테이너 + 마이그레이션 + 시드
.\scripts\setup.ps1 -WithDevFixtures # 위 + 템플릿 개발용 샘플 데이터(스팟·메이커·상품)까지
pnpm dev                             # http://localhost:3000
```

`.env.local` 은 루트에 하나만 둔다(웹·데이터 공용). 채워야 하는 값은 `.env.example` 참조.
최소한 `DATABASE_URL`, `ADMIN_TOKEN`, `AUTH_SECRET` 은 채워야 관리자가 동작한다.

수동으로 하려면:

```powershell
docker compose up -d db      # 또는 .\scripts\dev-db.ps1
pnpm install
pnpm db:migrate              # data/drizzle/ 의 SQL 적용
pnpm seed                    # 토픽·스팟유형·지역(229 시군구) + 콘텐츠 마크다운
pnpm seed:dev                # (선택) 샘플 픽스처 — 프로덕션에서 실행 거부됨
```

## 2. 일상 명령

| 명령 | 설명 |
|---|---|
| `pnpm dev` | Next 개발 서버 |
| `pnpm build` | 프로덕션 빌드 (DATABASE_URL 이 설정돼 있으면 DB가 켜져 있어야 한다) |
| `pnpm typecheck` / `pnpm test` | 전 패키지 타입체크 / 테스트 |
| `pnpm db:generate` | 스키마 변경 → 새 마이그레이션 SQL 생성 |
| `pnpm db:migrate` | 마이그레이션 적용 |
| `pnpm seed` | 기본 + 콘텐츠 시드 (멱등) |

## 3. 콘텐츠 워크플로

1. `data/content/guides/*.md` 에 frontmatter(slug/title/topic/role/status/medicalAdjacent…)와 본문 작성
2. `pnpm --filter @app/data seed:content` 로 DB 반영 (slug 기준 upsert)
3. 관리자(`/admin/guides`)에서 상태 전환·태깅. **원본은 git** — 시드 재실행이 관리자 본문 수정을 덮어쓴다는 점에 유의
4. 발행 규칙: 의료 인접(medicalAdjacent) 편은 `vetReviewed` 전에 published 불가 — 시드·관리자·DB 3중 차단

임베드는 본문에 숏코드로만: `{{youtube:VIDEO_ID|창작자명|원본URL}}`, `{{instagram:게시물URL|창작자명|원본URL}}`.
창작자명·원본 URL 누락 시 렌더되지 않는다 (규칙 3-4 의 코드 강제).

## 4. 공공데이터 ETL

### 4-1. 인허가 CSV (스팟·사료제조업 시딩)

data.go.kr 에서 각 인허가 데이터셋(동물미용업/동물위탁관리업/동물장묘업/동물운송업/사료제조업)의
CSV 를 내려받아 `data/raw/` (gitignore) 에 두고:

```powershell
.\scripts\etl.ps1 -Dataset animal-beauty -File data\raw\beauty.csv -ReferenceDate 2026-08-01
# 또는
pnpm etl:license -- --dataset animal-beauty --file data/raw/beauty.csv --reference-date 2026-08-01
```

동작 방식 (추측 금지 원칙):

- CSV 헤더를 `data/src/etl/license/mappings.ts` 의 후보명과 대조해 해석한다. **필수 컬럼(사업장명·관리번호)을
  못 찾으면 발견된 헤더 목록을 출력하고 실패한다.** 실제 파일 헤더가 다르면 mappings.ts 에 후보를 추가한다.
- 관리번호 기준 upsert — 재실행해도 중복이 생기지 않는다.
- 에디토리얼 필드(설명·요금·예약 링크·유형 재분류)는 절대 덮어쓰지 않는다.
- 시군구 미귀속·미매핑 영업상태는 `data/reports/*.json` 리포트에 남는다. 리포트를 보고 지역 별칭이나
  상태 매핑을 보강한 뒤 재실행하는 것이 정상 루프다.
- 인코딩은 `--encoding auto`(기본)가 BOM/깨짐 휴리스틱으로 처리. 이상하면 `cp949` 또는 `utf8` 명시.
- `--dry-run` 으로 DB 반영 없이 리포트만 뽑을 수 있다.

### 4-2. 동물등록 현황 (노령견 비율)

농림축산검역본부 동물등록 현황(시군구별 × 출생연도별)을 CSV 로 준비해:

```powershell
pnpm etl:stats -- --file data/raw/dog_registration.csv --reference-date 2026-06-30
```

`--reference-date` 는 필수다(통계는 기준일이 곧 의미). 적재 후 지역 페이지의
"등록견 중 노령견 비율" 블록이 자동으로 채워진다. API 활용신청이 승인되면 fetch 단계만 추가하면 된다
(정규화·적재 재사용).

### 4-3. 직접 발굴 데이터

셀프목욕·방문목욕·재활(수중런닝머신)·기기 보유처는 공공데이터에 없다. 현재 입력 경로:

- 스팟: 관리자에서 직접 추가하는 UI 는 아직 없다 — SQL 또는 시드 스크립트로 `source='direct'` 로 넣고,
  이후 관리자 편집으로 정보를 보강한다 (관리자 스팟 신규 생성 폼은 다음 작업 후보).
- 기기·보유처: `device_models` / `device_sites` 테이블에 직접 입력.

## 5. 관리자

- `/admin/login` — `.env.local` 의 `ADMIN_TOKEN` 으로 로그인 (Cognito 전환 전 임시 인증, `web/src/lib/auth.ts` 만 교체하면 됨)
- 가이드: 상태 전환, 본문 수정, **개체 태깅**(상품·스팟·메이커 연결 + 맥락 라벨)
- 클레임: `/claim/spot/[id]`, `/claim/maker/[id]` 로 접수된 요청 승인·반려. 연락처는 확인 용도로만.
- 스팟: 정보 보강(운영시간·요금 등 — noindex 게이트 통과 수단), 유형 재분류, 지역 상단 노출 토글(장묘 불가)

## 6. SEO 동작 확인

- 로컬(`NEXT_PUBLIC_SITE_URL` 이 localhost)에서는 **모든 페이지가 noindex + robots 전면 차단** — 사고 방지 가드.
- 프로덕션 URL 설정 시: 스팟 3곳 미만 지역, 정보 3항목 미만 장소, 언급 0건 상품 등이 noindex 로 빠진다.
- 사이트맵: `/sitemap.xml` (인덱스) → `/sitemaps/{core,guides,spots,places,makers,items,curations}.xml`.
  게이트에 걸리는 URL 은 사이트맵에서도 제외된다 (기준 공유: `web/src/lib/queries/sitemap.ts`).
- 재검증 주기는 `web/src/lib/revalidate.ts` 가 단일 소스 — 페이지 리터럴과 어긋나면 테스트가 깨진다.
