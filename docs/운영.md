# 운영 가이드 — 로컬 개발과 데이터 파이프라인

## 0. 사전 준비 (최초 1회)

| 항목 | 확인 | 없으면 |
|---|---|---|
| Node **22 LTS** | `node --version` | https://nodejs.org (22.x LTS) |
| **pnpm** (npm/yarn 금지) | `pnpm --version` | `corepack enable pnpm` |
| Docker Desktop | `docker --version` | https://docker.com — 또는 로컬 PostgreSQL 사용(아래 1-2) |
| Git | `git --version` | https://git-scm.com |

PowerShell 실행 정책 때문에 `.ps1` 이 막히면 그 창에서만 임시 허용:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

## 1. 클론부터 실행까지

### 1-1. 기본 경로 (Docker 사용)

```powershell
git clone https://github.com/likethisfeelo/petlifewith.me.git C:\petlifewithme
cd C:\petlifewithme
git checkout claude/build-from-spec-qkpshy

.\scripts\setup.ps1 -WithDevFixtures   # 아래 5단계를 한 번에
pnpm dev                                # http://localhost:3000
```

`setup.ps1` 이 하는 일:

1. 사전 준비 확인 (node 22+, pnpm, docker)
2. **`.env.local` 생성** — docker-compose 와 맞는 `DATABASE_URL` + 무작위 생성한
   `ADMIN_TOKEN`·`AUTH_SECRET`. (`.env.example` 은 변수명만 있는 목록이라 복사하지 않는다.
   복사하면 `DATABASE_URL` 이 비어 마이그레이션이 실패한다.)
3. `pnpm install`
4. `docker compose up -d db` + **접속 가능해질 때까지 대기**(`pg_isready` 폴링)
5. `pnpm db:migrate` → `pnpm seed` (+ `-WithDevFixtures` 면 `pnpm seed:dev`)

끝나면 관리자 토큰을 화면에 찍어준다. `.env.local` 이 이미 있으면 건드리지 않는다.

`-WithDevFixtures` 는 페이지 템플릿을 눈으로 확인하기 위한 **샘플 데이터**(샘플 스팟 8·메이커 2·
상품 4·클레임 1)를 넣는다. 전부 이름에 "샘플"이 붙고 `source='sample'` 이라 색인·사이트맵에서 제외되며,
실데이터를 넣기 시작하면 지우면 된다.

### 1-2. Docker 없이 (로컬 PostgreSQL 사용)

PostgreSQL 16 을 직접 설치했다면 DB·롤을 먼저 만들고 URL 을 넘긴다.

```powershell
# psql 에서
# CREATE ROLE app WITH LOGIN PASSWORD 'app_dev_password' CREATEDB;
# CREATE DATABASE app_dev OWNER app;

.\scripts\setup.ps1 -SkipDocker -DatabaseUrl 'postgresql://app:app_dev_password@localhost:5432/app_dev'
```

### 1-3. 수동으로 한 단계씩

```powershell
docker compose up -d db      # 또는 .\scripts\dev-db.ps1
pnpm install
pnpm db:migrate              # data/drizzle/ 의 SQL 적용
pnpm seed                    # 토픽 5 · 스팟유형 10 · 시군구 229 + 콘텐츠 18편
pnpm seed:dev                # (선택) 샘플 픽스처 — 프로덕션에서 실행 거부됨
pnpm dev
```

이 경로로 갈 때는 `.env.local` 을 직접 만들어야 한다. 루트에 하나만 두며(웹·데이터 공용),
최소 `DATABASE_URL`·`ADMIN_TOKEN`·`AUTH_SECRET` 이 있어야 앱과 관리자가 동작한다.
전체 변수 목록은 `.env.example`.

## 3. 콘텐츠 워크플로

1. `data/content/guides/*.md` 에 frontmatter(slug/title/topic/role/status/medicalAdjacent…)와 본문 작성
2. `pnpm --filter @app/data seed:content` 로 DB 반영 (slug 기준 upsert)
3. 관리자(`/admin/guides`)에서 상태 전환·태깅. **원본은 git** — 시드 재실행이 관리자 본문 수정을 덮어쓴다는 점에 유의
4. 발행 규칙: 의료 인접(medicalAdjacent) 편은 `vetReviewed` 전에 published 불가 — 시드·관리자·DB 3중 차단

임베드는 본문에 숏코드로만: `{{youtube:VIDEO_ID|창작자명|원본URL}}`, `{{instagram:게시물URL|창작자명|원본URL}}`.
창작자명·원본 URL 누락 시 렌더되지 않는다 (규칙 3-4 의 코드 강제).

## 4. 공공데이터 ETL

### 4-1. 인허가 CSV (스팟·사료제조업 시딩)

행정안전부 지방행정 인허가데이터(공공데이터포털 data.go.kr)의 CSV 를 내려받아
`data/raw/` (gitignore — 원본 덤프 커밋 금지) 에 두고 실행한다. 지원 데이터셋:

| `--dataset` | 원천 (행안부 인허가) | 스팟 유형 | 공개 정책 |
|---|---|---|---|
| `animal-beauty` | 동물미용업 | 미용·스파 | 공개 디렉토리 |
| `animal-boarding` | 동물위탁관리업 | 유치원·위탁 | 공개 디렉토리 |
| `animal-memorial` | 동물장묘업 | 장묘 | 공개 — **광고·순위 없음** |
| `animal-transport` | 동물운송업 | 이동·운송 | 공개 (행 단위가 차량이라 이름이 차량번호인 행이 많다 — noindex 게이트가 거른다) |
| `animal-pharmacy` | 동물약국 | 동물약국 | 공개 — **광고·순위 없음, 수의사 안내문 자동** (규칙 6-2) |
| `animal-drug-wholesale` | 동물용의약품 도매상 | 동물용의약품 도매 | **B2B 참고 디렉토리** — 광고 없음, 소비자 목록·집계와 분리 게시 |
| `animal-medical-device` | 동물용 의료용구 판매업 | 동물용 의료용구 판매 | **B2B 참고 디렉토리** — 상동 |
| `feed-manufacture` | 사료제조업 | (feed_licenses 원장) | 메이커 배지 근거 |

`spot_types.listed` 는 **소비자 디렉토리 배치 여부**다. listed=false(B2B 참고) 유형도
유형 허브·지역x유형·개별 페이지로 게시되지만(B2B 안내문 자동), 지역 허브의 혼합 목록·유형
분포·시도/시군구 집계에는 섞이지 않고 별도 "유통·산업 (B2B 참고)" 줄로만 연결된다.
색인·사이트맵 게이트(3곳·3항목)는 전 유형 동일하게 적용된다.
모든 공개 표기는 "행정안전부 지방행정 인허가데이터 확인 자료 · 기준일 · 관리번호"를 명시한다.

2026-08-25 실적재: 미용업 16,107 / 운송업 4,643 / 동물약국 20,796 / 도매상 1,316 / 의료용구 3,345
(스킵 1건 — 정부 원본이 2014년 폐지된 "청원군" 주소를 담은 폐업 행, 리포트에 기록됨).

**2026 행정구역 개편 대응** (`data/src/regions/regions.ts`):

- `전남광주통합특별시` 표기는 시군구명으로 옛 광주(구 5)·전남(시·군 22)에 결정적으로 귀속된다
  (`MERGED_SIDO_SLUGS`). URL 체계(/spot/시도/시군구)는 그대로다.
- 인천 신설 4개 구(제물포·영종·검단·서해)를 지역 테이블에 추가했다 (229 → 233).
  동구·서구는 기존 URL·데이터 보존을 위해 남아 있다.

```powershell
# 로컬 DB(.env.local) 대상
.\scripts\etl.ps1 -Dataset animal-beauty -File data\raw\beauty.csv -Encoding cp949 -ReferenceDate 2026-08-01
# 배포된 dev/prod DB 대상 — .env.deploy.<stage> 의 DATABASE_URL 을 자동 사용
.\scripts\etl.ps1 -Stage dev -Dataset animal-beauty -File data\raw\beauty.csv -Encoding cp949 -ReferenceDate 2026-08-01
# 스키마가 바뀐 뒤라면 적재 전에 마이그레이션·기준 시드 먼저:
.\scripts\db.ps1 -Stage dev
```

`.\scripts\db.ps1 -Stage dev -Task status` 로 접속 대상과 적재 현황(테이블·유형별 스팟 수)을
언제든 확인할 수 있다. 한글 파일명은 인자로 전달해도 된다 (.ps1 파일 내용만 ASCII 제한).

동작 방식 (추측 금지 원칙):

- CSV 헤더를 `data/src/etl/license/mappings.ts` 의 후보명과 대조해 해석한다. **필수 컬럼(사업장명·관리번호)을
  못 찾으면 발견된 헤더 목록을 출력하고 실패한다.** 실제 파일 헤더가 다르면 mappings.ts 에 후보를 추가한다.
- 관리번호 기준 upsert — 재실행해도 중복이 생기지 않는다.
- 에디토리얼 필드(설명·요금·예약 링크·유형 재분류)는 절대 덮어쓰지 않는다.
- 시군구 미귀속·미매핑 영업상태는 `data/reports/*.json` 리포트에 남는다. 리포트를 보고 지역 별칭이나
  상태 매핑을 보강한 뒤 재실행하는 것이 정상 루프다.
- 인코딩은 `--encoding auto`(기본)가 BOM/깨짐 휴리스틱으로 처리. 이상하면 `cp949` 또는 `utf8` 명시.
- `--dry-run` 으로 DB 반영 없이 리포트만 뽑을 수 있다.

### 4-2. 동물등록 현황 (노령견 비율)

농림축산검역본부 동물등록 현황(시군구별 × 출생연도별)을 CSV 로 준비해:

```powershell
pnpm etl:stats -- --file data/raw/dog_registration.csv --reference-date 2026-06-30
```

`--reference-date` 는 필수다(통계는 기준일이 곧 의미). 적재 후 지역 페이지의
"등록견 중 노령견 비율" 블록이 자동으로 채워진다. API 활용신청이 승인되면 fetch 단계만 추가하면 된다
(정규화·적재 재사용).

### 4-3. 직접 발굴 데이터

셀프목욕·방문목욕·재활(수중런닝머신)·기기 보유처는 공공데이터에 없다. **관리자에서 직접 등록한다** —
`/admin/spots/new` 로 넣으면 출처가 `direct` 로 기록되고, 기기와 보유처는 `/admin/devices/new` 에서
등록한다. ETL 재실행은 인허가 원천 필드만 갱신하므로 여기서 넣은 정보는 덮어쓰지 않는다.

## 4-4. 애널리틱스·검색 등록 (GTM / GA4 / Search Console)

- **GTM 컨테이너** `GTM-TH2GC5MP` 를 전 공개 페이지에 설치(스크립트 + noscript). 값은
  `web/src/lib/config.ts` 에 기본값으로 있고 `NEXT_PUBLIC_GTM_ID` 로 덮어쓰거나 `off` 로 끈다.
- **GA4 측정 ID** `G-54XBW1L9KE` 는 **GTM 안에서 "GA4 구성" 태그로 설정한다.** 코드가
  gtag.js 를 따로 넣지 않는 이유는 중복 집계(페이지뷰 2배) 때문이다.
  GTM 을 쓰지 않기로 하면 `NEXT_PUBLIC_GTM_ID=off` — 그때만 GA4 를 직접 로드한다.
- **Search Console 소유 확인** 메타 태그는 전 페이지 `<head>` 에 들어간다
  (`NEXT_PUBLIC_GOOGLE_SITE_VERIFICATION`). 배포 후 GSC 에서 "HTML 태그" 방식으로 확인을 누르면 된다.
- **수집 범위 (코드 강제, `web/src/lib/analytics.ts` + 테스트)**
  - `production` 에서만 로드 — dev(preview)·로컬 트래픽이 통계에 섞이지 않는다.
  - **관리자 제외**: `/admin/*` 경로와 `admin.` 서브도메인(경로가 `/` 로 보이는 경우 포함).
    내부 사용량 왜곡과 관리 URL(개체 ID 포함)의 외부 전송을 막는다.
  - 사장님 포털(`service.` / `product.`)은 실제 사용자 화면이라 **수집한다.**

## 5. 관리자

`/admin/login` — `ADMIN_TOKEN` 으로 로그인 (Cognito 전환 전 임시 인증,
`web/src/lib/auth.ts` 만 교체하면 됨). 등록·편집이 전부 관리자에서 됩니다.

### 5-0. 관리자 계정 (사람별 토큰)

`ADMIN_TOKEN` 하나에 계정 여러 개를 담습니다 — `hee:<토큰1>,partner:<토큰2>`.
사람마다 다른 토큰을 주면 **개별 회수**가 되고, 패널 우측 상단에 로그인한 계정 라벨이 보입니다.

```powershell
.\scripts\admin-token.ps1 -Stage prod -List          # 등록된 계정 (토큰은 출력 안 함)
.\scripts\admin-token.ps1 -Stage prod -Add hee       # 계정 추가 + 토큰 1회 출력
.\scripts\admin-token.ps1 -Stage prod -Remove hee    # 회수
.\scripts\admin-token.ps1 -Generate                  # 파일은 그대로, 토큰만 생성
```

- `-Stage local` 은 `.env.local`(개발 서버 재시작), `dev`/`prod` 는 `.env.deploy.<스테이지>` 를
  고칩니다. 배포에 반영하려면 **GitHub 시크릿(`ENV_DEPLOY_DEV`/`ENV_DEPLOY_PROD`) 갱신 후 재배포** —
  스크립트가 그 절차를 출력합니다.
- 세션에는 토큰 지문만 들어갑니다. 계정을 빼거나 토큰을 갈면 **그 사람의 기존 로그인도 즉시 끊깁니다.**
- 토큰은 발급 시 한 번만 보입니다. 비밀번호 관리자 등 비공개 경로로 전달하고 채팅·커밋에 붙여넣지 않습니다.
- 마지막 한 계정은 지워지지 않습니다(아무도 못 들어가는 상태 방지).
- `service.` / `product.`(사장님 포털)는 **로그인이 없는 공개 랜딩 페이지**라 계정 설정이 없습니다.
  업주 셀프 로그인은 Cognito 도입 시점에 생깁니다.

| `/admin/items` `/new` `/[id]` | 상품 등록·편집, 구매 링크(쿠팡 파트너스 포함) |
| `/admin/devices` `/new` `/[id]` | 기기 등록·편집, 보유처 목록 |
| `/admin/curations` `/new` `/[id]` | 큐레이션 테마·항목 등록 |
| `/admin/claims` | 클레임 승인·반려 (연락처는 확인 용도로만, 비공개) |

### 5-1. 외부 링크 (선택적)

스팟과 메이커의 링크는 고정 항목이 아니라 **필요한 것만 골라 넣는 목록**입니다
(`spot_links` / `maker_links`). 업체마다 쓰는 채널이 다르기 때문입니다.

- 스팟: 홈페이지 · 카카오톡 · 예약 · 네이버 플레이스 · 인스타그램 · 블로그 · 기타
- 메이커: 자사몰 · 스마트스토어 · 카카오톡 · 인스타그램 · 크라우드펀딩 · 블로그 · 기타
- `http://` `https://` 만 저장됩니다. 주소가 빈 행은 저장 시 조용히 버려집니다.
- **링크도 정보 항목으로 셉니다.** 주소·전화만 있어 2항목이던 장소도 카카오톡 링크 하나로
  3항목이 되어 색인 대상이 됩니다 (claude.md 5-3).

### 5-2. 쿠팡 파트너스 링크

상품 편집의 구매 링크에서 구매처를 **쿠팡**으로 고르면 제휴 링크로 저장됩니다(직접 체크도 가능).
제휴 링크가 하나라도 렌더되는 페이지에는 수수료 고지가 자동으로 붙고, 링크에 `rel="sponsored"`
가 붙습니다. 본문 마크다운에 넣은 `link.coupang.com` 주소도 렌더러가 같은 처리를 합니다.

### 5-3. 미디어 업로드 (이미지·영상)

업로드는 처음부터 S3 전제다 (claude.md 10-1) — 서버는 presigned URL 만 발급하고
브라우저가 스토리지에 직접 올린다. 로컬에서는 MinIO 가 S3 를 대신한다.

```powershell
docker compose up -d minio        # minio-init 이 app-media 버킷을 만들고 공개 읽기로 연다
```

`.env.local` (setup.ps1 이 생성한 파일에는 이미 이 기본값이 들어 있다):

```
STORAGE_ENDPOINT=http://localhost:9000
STORAGE_BUCKET=app-media
STORAGE_ACCESS_KEY_ID=minio_dev
STORAGE_SECRET_ACCESS_KEY=minio_dev_password
NEXT_PUBLIC_ASSET_BASE_URL=http://localhost:9000/app-media
```

`NEXT_PUBLIC_*` 은 빌드에 인라인되므로 값을 바꾸면 dev 서버를 재시작한다.

- **미디어 라이브러리** `/admin/media` — 업로드(이미지 15MB·영상 300MB), 숏코드 복사, 삭제
- **본문 삽입** — 숏코드만 쓴다. DB 에는 오브젝트 키만 저장되고 URL 은 렌더 시 조립된다:
  `{{image:키|대체텍스트|캡션(선택)}}` · `{{video:키|캡션(선택)}}`
- **대표 이미지** — 게시글·스팟·메이커·상품 에디터의 업로드 필드. 페이지 상단과 공유 미리보기에 쓰인다
- **원칙**: 직접 촬영·제작한 것만. 인스타그램·유튜브에서 내려받은 이미지·스크린샷 업로드는 금지 (규칙 3-1).
  삭제하면 그 키를 쓰는 본문·OG 이미지가 깨진다 — 교체는 삭제가 아니라 새로 올려서 바꾼다.

배포 전환 시: 버킷을 S3 로, `NEXT_PUBLIC_ASSET_BASE_URL` 을 CloudFront 도메인으로 바꾸면 끝
(키는 그대로라 콘텐츠 수정이 필요 없다).

### 5-4. 페이지별 SEO / OG 설정

모든 공개 페이지는 og:title / og:description / og:url / og:image / og:type / twitter 카드가
자동으로 붙는다 (`web/src/lib/seo.ts` buildMeta). 기본값은 제목·요약·대표 이미지에서 만들어지고,
따로 다듬고 싶은 페이지만 에디터의 **"검색·공유 설정 (SEO / OG)"** 섹션에서 오버라이드한다.

- 대상: 게시글 · 스팟 · 메이커 · 상품 · 큐레이션 (검색·공유 제목 / 설명 / OG 이미지)
- 우선순위: 오버라이드 → 대표 이미지 → 사이트 기본 이미지(`NEXT_PUBLIC_DEFAULT_OG_IMAGE_URL`)
- 권장 길이(제목 60자·설명 155자)를 넘으면 카운터가 경고색으로 바뀌고, 70/200자를 넘으면 저장이 거부된다
- 게시글·큐레이션은 `og:type=article` + 발행·수정 시각, JSON-LD Article 에도 이미지가 들어간다

### 5-5. 게시글 작성 (블로그형)

`/admin/guides/new` 에서 바로 씁니다. 마크다운 파일(`data/content/guides/*.md`)로 관리하는
경로와 공존합니다 — **같은 슬러그를 쓰면 `seed:content` 재실행 시 본문이 덮어써지니**, 관리자에서
쓴 글은 마크다운에 없는 슬러그를 쓰세요. 저장하면 편집 화면으로 이동해 태깅을 붙일 수 있습니다.

저장 시 막히는 것들: 의료 인접 편의 즉시 발행, 감수자명 없는 감수 완료 표시, 기준일 없는 등록
확인 배지, 창작자명·원본 링크·요약이 빠진 큐레이션 항목, `http(s)` 가 아닌 링크.

## 6. SEO 동작 확인

- 로컬(`NEXT_PUBLIC_SITE_URL` 이 localhost)에서는 **모든 페이지가 noindex + robots 전면 차단** — 사고 방지 가드.
- 프로덕션 URL 설정 시: 스팟 3곳 미만 지역, 정보 3항목 미만 장소, 언급 0건 상품 등이 noindex 로 빠진다.
- 사이트맵: `/sitemap.xml` (인덱스) → `/sitemaps/{core,guides,spots,places,makers,items,curations}.xml`.
  게이트에 걸리는 URL 은 사이트맵에서도 제외된다 (기준 공유: `web/src/lib/queries/sitemap.ts`).
- 재검증 주기는 `web/src/lib/revalidate.ts` 가 단일 소스 — 페이지 리터럴과 어긋나면 테스트가 깨진다.

## 8. 자주 막히는 것

| 증상 | 원인과 해결 |
|---|---|
| `환경변수 DATABASE_URL 가 없습니다` | `.env.local` 이 없거나 값이 비어 있다. `.env.example` 을 그대로 복사하면 값이 전부 비어 있으니 `setup.ps1` 로 생성하거나 직접 채운다 |
| `ECONNREFUSED 127.0.0.1:5432` | DB 가 안 떠 있다. `.\scripts\dev-db.ps1` 또는 `docker compose up -d db`. 컨테이너 기동 직후 몇 초는 접속이 거부될 수 있다 |
| `.ps1` 실행이 차단됨 | `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` 후 재실행 |
| `pnpm: 명령을 찾을 수 없음` | `corepack enable pnpm`. npm·yarn 은 쓰지 않는다 |
| `pnpm build` 가 DB 오류로 실패 | 빌드가 페이지를 미리 생성하며 DB 를 읽는다. 빌드 전에 DB 를 띄워둔다 |
| 관리자 로그인이 계속 실패 | `.env.local` 의 `ADMIN_TOKEN` 과 입력값이 정확히 같아야 한다. `AUTH_SECRET` 이 비어 있어도 로그인은 실패한다 |
| 발행한 글이 안 보임 | `status: published` 인지, 의료 인접 편이면 `vetReviewed: true` 인지 확인 (감수 전 발행은 차단된다) |
